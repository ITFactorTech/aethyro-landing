Call Aethyro's models from your own code — scripts, backend services, CI pipelines. No SDK required: it's a single JSON endpoint, billed in credits per request, same rates as the chat app.

Quickstart

Create a key from your dashboard, then:

curl -X POST https://uzmdqbtflcpikjdrggqc.supabase.co/functions/v1/api-chat \
  -H "Authorization: Bearer ak_live_..." \
  -H "Content-Type: application/json" \
  -d '{"message": "Summarize the plot of Dune in two sentences.", "model": "sonnet"}'
{
  "model": "sonnet",
  "content": "...",
  "usage": { "input_tokens": 18, "output_tokens": 64 },
  "credits_charged": 1,
  "credits_remaining": 199
}

Authentication

Every key starts with ak_live_. Pass it as a bearer token — the API never sees or needs your Aethyro login, so it's safe to use from a server or CI job (never from client-side browser code, since anything in browser JS is visible to whoever loads the page). Keys are shown once at creation; if you lose one, revoke it and create a new one.

Authorization: Bearer ak_live_...

Request

POST /functions/v1/api-chat — stateless: send the full conversation each time, same as most completion APIs. There's no server-side conversation history on this path.

FieldTypeNotes
messagestringShorthand for a single user turn. Use this or messages, not both.
messagesarray[{role: "user"|"assistant", content: string}], up to 20 entries, must end with a user turn.
modelstringhaiku / sonnet / opus. Defaults to sonnet.

Errors

502The upstream model call failed. Safe to retry.
A note on scope, honestly:

This is a v1. Each key is capped at 30 requests/minute (on top of your credit balance) — you'll get a 429 with Retry-After: 60 if you hit it. No streaming responses yet, and no auto model routing on this endpoint (that's chat.html-only for now) — just a single synchronous JSON call. If you need either of those, or a higher rate limit, tell us.
